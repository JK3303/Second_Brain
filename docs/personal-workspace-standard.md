# Personal workspace standard

Version: 0.2.0
Status: draft; implementation and review do not establish personal adoption.

This standard describes shared behavior, not identical personal goals, folders,
permissions, or retention settings. Local human choices remain authoritative.

1. Provide one clear entry point describing readiness, where work lives, and how
   to begin or resume. Opening or cloning a project does not activate it.
2. Maintain personal working agreements. Match language and experience, explain
   consequential choices, and carry out authorized routine work without forcing
   every task into a lesson.
3. Distinguish confirmed intentions, proposals, historical priorities, and unknowns.
   None supplies permission to publish, spend, connect accounts, or change access.
4. Revise only the requested scope. Preserve settled content and authorship; do
   not invent facts, personal meaning, or approval. Explain substantive changes.
5. Keep one stable current deliverable, preserve the previous working version until
   replacement succeeds, and read back the saved result. Local, uploaded, published,
   and shared are separate states; verify each requested destination independently.
6. Resume from evidence: what happened, its source, unresolved questions, and the
   smallest useful next step. Missing records remain missing; expired plans do not
   automatically become current obligations. No mandatory cadence or tracking.
7. Declare actual memory and privacy boundaries. Retain only authorized material;
   private state stays outside Git. A repository is not a complete private-history
   backup. Report incomplete capture and unavailable evidence accurately.
8. Upgrade deliberately. Record the standard version and source digest, reference
   local adaptations without duplicating them, preserve personal content, and
   advance adoption only after explicit review and relevant verification.

## Portable record

`workspace-standard.json` identifies this standard, its exact SHA256, adoption
status, references to local adaptations, and verification evidence. The portable
copy is `docs/personal-workspace-standard.md`. Runtime/package versions are separate.
Draft, proposed, verified, and adopted are different states. No automatic updater
or synchronization is authorized. A conflict requires review, not silent precedence.

## Origin and limits

This draft describes generic personal-workspace methods: confirmed intentions,
focused revision, stable delivery, and evidence-based resumption. Only reusable
methods transfer; personal records, goals, specialized workflows, and permissions
do not. Documented practices are not measured effectiveness.

This distribution retains standard version 0.2.0 and its behavioral rules. Its
origin paragraph is generalized for public distribution; metadata records the
upstream digest separately from this copy's actual digest. It is not byte-identical
to the upstream standard. No new behavioral release is claimed.

New repository-based setup retains explicit agreement/profile review, individually
selected input files, and external private state. Existing workspaces can adopt
the standard without running new-instance setup or enabling capture. Capture mode
requires Windows and macOS live capture checks for the selected runtime; fixture
passes do not satisfy them. Records-only use requires no live capture test.
Library capabilities are optional and separately governed.

## Mind, Memory, and Work

Mind supplies independent judgment under the person's direction. Memory retrieves
attributed, correction-aware records within their approved scope. Work defines the
outcome, carries out authorized steps, and verifies each delivery destination.
These describe behavior, not a mandatory pipeline or identical tools.

Raw-session capture is optional. Records mode retains only approved records and
notes; a statement is attributed testimony, not transcript evidence. Captured
session references are available only under separate capture approval. No record
is required for every conversation. Application/provider logging is separate.

## Coordinated releases and local adaptation

Each receiving workspace pins this standard's version, exact SHA256, and source
revision, and references its own working agreements and continuity method.
An existing workspace can retain its cadence and records; a new personal workspace can choose
records or capture after explicit setup review. Mira Core retains its own governed
carriers. Tools and generic methods may transfer; personal records and approvals do
not. Draft PR references remain candidates until their Core source has landed.
A merge does not establish personal adoption, capture permission, or data sharing.
