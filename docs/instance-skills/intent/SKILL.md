# Intent capability 1.0.0

Use for enduring purposes, emphasis, or an explicit intent review. Use
intent-recovery for a compressed current request. Ordinary tasks need neither
a full intent review nor a saved record. The person owns their intentions.

Read `docs/intent-capability.md` before a revision or acceptance. Recover through
`python tools/intent.py context`; preserve IDs, qualifications, attributed human
confirmation, digest, revision, and runtime acceptance as separate evidence.
Use only the relevant content. Unavailable state is an evidence gap, never a
reason to invent goals, initialize storage, or block independently authorized help.

Propose changes conversationally unless saving was requested. A reviewed revision,
canonical write, exact-digest acceptance, and authorized execution are different
decisions. Reuse actual authorization without inventing consent from a metadata
field. Preserve the person's language and existing local working agreements.
Intent acceptance grants no publication, spending, account, or execution authority.

After an authorized write, read back context and verify the exact bytes, digest,
acceptance and history. Missing approval remains missing. Never automatically
accept, activate, resume preparation, synchronize, or rewrite qualified prose.
