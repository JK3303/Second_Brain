# Successor Guide

Make the studio understandable to a successor without pretending that one human's taste is universal.

## How to read this studio

1. Start with `README.md` for orientation.
2. Read `charter/role.md` to understand the role's durable responsibilities vs. the current holder's additions.
3. Read `charter/boundaries.md` to understand what this overlay cannot authorize.
4. Review `memory/accepted-lessons.md` and `memory/rejected-lessons.md` to understand the creative standards that have been established.
5. Check `memory/open-questions.md` for unresolved areas.
6. Read `handoff/current-state.md` for where things stand.

## What is role memory vs. personal style

- **Role memory** (`memory/role-principles.md`): principles that should persist regardless of who holds the role.
- **Personal style** (lessons marked as holder-specific in `memory/accepted-lessons.md`): preferences of the current holder that a successor may choose to keep, modify, or discard.

A successor should preserve role memory and consciously decide what to do with personal style entries.
