# Review PDF Outline

> **Template.** Structure for the decision package. Copy to the approved private engagement surface and fill with engagement content there.

**Format:** landscape · approximately 20 pages · one idea per page
**Required mark on every page:** `Confidential review draft — no implementation or publication authorized.`

---

## Page map

| Page | Content |
|------|---------|
| 1 | **Cover** — client name, engagement title, date, prepared-by, confidentiality mark, draft status |
| 2 | **Decision requested** — the five available decisions, who holds the authority, what a selection does *not* authorize, and the deadline if any |
| 3 | **Current brand reading** — observations, what carries the brand today, equity to preserve, and what is explicitly not asserted |
| 4 | **Shared objectives and constraints** — what all three proposals are trying to do, and the constraints all three respect |
| 5 | **Evaluation criteria** — the nine criteria, plain-language, so the decision-maker can apply their own weighting |
| 6–9 | **Proposal A** |
| 10–13 | **Proposal B** |
| 14–17 | **Proposal C** |
| 18 | **Side-by-side comparison** — score matrix, the real fork, combinable elements |
| 19 | **AD recommendation** — recommendation, reasoning, strongest preserved alternative, principal risk, what would change the judgment |
| 20 | **Decision page** — the five options, space for reasons in the decision-maker's own words, signature and date |

---

## Proposal page structure — identical for A, B, and C

Every proposal uses these four pages in this order. No proposal gets a fifth page; none gets three.

| Offset | Page | Content |
|--------|------|---------|
| +0 | **Territory** | Name · one-sentence premise · centre of gravity · positioning · customer promise · intended audience response (labeled as hypothesis) |
| +1 | **Identity** | Logo or naming treatment · palette · typography · imagery, materials, and graphic language |
| +2 | **Applications** | The agreed representative applications — same types and count across all three · placeholders visibly marked on the artefact itself |
| +3 | **Assessment** | Strengths · risks · assumptions · uncertainties · evidence and provenance summary · implementation implications with the non-authorization note |

---

## Standing rules

1. **Parity is structural.** Same page count, same section order, same application types, comparable density. Asymmetry pre-decides the outcome.
2. **Placeholders are marked on the artefact.** A register entry is not enough — the decision-maker must see it on the page.
3. **Provenance is visible.** Each application page carries its asset provenance labels.
4. **Claim types are visible.** Hypotheses are labeled as hypotheses on the page, not only in the source document.
5. **Reserved words are prohibited** — *approved, selected, signed off, agreed, confirmed, final, authorized* — except where describing what has *not* happened.
6. **The recommendation and the decision are on separate pages,** in that order, visually distinct.
7. **Editable sources are preserved** alongside the render, and listed in the asset register.
8. **The render is opened and visually inspected** before delivery. A clean build is not an inspection.

## Pre-delivery check

- [ ] Page count matches the map
- [ ] All three proposals use the identical four-page structure
- [ ] Confidentiality mark on every page
- [ ] Every placeholder visibly marked
- [ ] Provenance labels present on application pages
- [ ] No reserved words misused
- [ ] Recommendation separated from decision page
- [ ] Decision page includes all five options
- [ ] Render opened and visually inspected by a human
- [ ] Editable sources preserved and registered
