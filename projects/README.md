# Projects

| Project | Owner | State |
|---------|-------|-------|
| [Artistic Director](artistic-director/) | JK | Active — internal |

Project inclusion does not authorize publication, deployment, spending, external contact, client decisions, or company decisions. Each project operates within its own authority boundaries.

Reusable work moves from `projects/` into `recipes/`, `skills/`, or another shared surface only through a separate review.

## Per-project README requirements

Each project README must identify:

- **Owner** — who holds creative and decision authority
- **Purpose** — what the project is for
- **State** — current phase (prototype, active, paused, complete)
- **AI contribution** — how AI systems are used in the project
- **External-authority boundary** — what the project cannot authorize
- **Current entry point** — where to start reading
- **Next review** — what happens next and who decides
